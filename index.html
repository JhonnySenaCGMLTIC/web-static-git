Comprende la diferencia

Uno de los errores más comunes de un aprendiz es confundir Git con GitHub. Aquí te lo explicamos con precisión técnica.

Herramienta Local

¿Qué es Git?

Git es un sistema de control de versiones distribuido gratuito y de código abierto. Funciona directamente en tu computador local a través de la terminal o consola.

  • ✓ Registra el historial de cambios archivo por archivo mediante commits.
  • ✓ Permite crear ramificaciones (branches) para trabajar en nuevas funciones sin dañar el proyecto base.
  • ✓ Funciona sin necesidad de conexión a internet.
Sitio oficial de Git (Descargas y Documentación)
Plataforma en la Nube

¿Qué es GitHub?

GitHub es una plataforma de alojamiento en la nube que almacena repositorios de Git. Es el punto de encuentro donde instructores y aprendices comparten código, colaboran y revisan proyectos formativos.

  • ✓ Almacena respaldos remotos de tus proyectos en servidores seguros.
  • ✓ Facilita la revisión de código mediante Pull Requests e Issues.
  • ✓ Funciona como portafolio profesional para ingresar a la industria TI.

Guía Paso a Paso

Flujo de Trabajo Estándar

Los cuatro pasos fundamentales que todo aprendiz SENA aplica en proyectos formativos y ambientes empresariales.

1
Paso 01

Crear o Clonar el Repositorio

Inicia un repositorio nuevo dentro de la carpeta de tu proyecto o descarga una copia de un repositorio grupal existente desde GitHub.

# Iniciar repositorio local nuevo:

$ git init

# O clonar un proyecto existente del instructor:

$ git clone https://github.com/usuario/proyecto-sena.git

2
Paso 02

Preparar y Confirmar Cambios (Stage & Commit)

Agrega los archivos modificados al área de preparación (staging area) y guarda una foto histórica de tu código con un mensaje descriptivo.

# Preparar todos los archivos modificados:

$ git add .

# Crear el punto de control con mensaje claro:

$ git commit -m "feat: interfaz de formulario de matrícula"

3
Paso 03

Subir a la Nube (Git Push)

Transfiere tus confirmaciones locales hacia el repositorio remoto en GitHub para que tus compañeros e instructores tengan acceso.

# Subir rama principal al repositorio remoto:

$ git push -u origin main

# O enviar tu rama de funcionalidad:

$ git push origin mi-rama-de-trabajo

4
Paso 04

Crear un Pull Request (PR) y Revisión

Desde la plataforma GitHub, solicita la integración de tus cambios a la rama principal. El instructor o líder técnico del equipo revisará y aprobará el código antes de fusionarlo (merge).

¡Buenas prácticas SENA! Nunca hagas push directo a main en proyectos de equipo; utiliza siempre ramas y Pull Requests.
